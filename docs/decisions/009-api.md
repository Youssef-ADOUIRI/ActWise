# 009: API guards: one deadline per request, and a daily cap kept in memory

- **Options:**
  - **Time limit:** a 25 s budget per model call (step 5), or one deadline for the whole request.
  - **Daily cap (R6):** count on each instance in memory, or share one count in Firestore.
  - **A spent quota:** ask that provider again on every request, or skip it until its Retry-After has passed.
- **Measured (local run, `gemini-3.5-flash-lite`):**
  - **Latency:** `/ask` answered in 2.1–2.9 s, and `/classify` and `/upload` in 1.4–2.8 s.
  - **The cap:** with `MAX_DAILY_REQUESTS=5`, the sixth request got 429 in 0.2 s, with no model call.
  - **Classifications:** all three matched their dev labels: s05 (prohibited) as JSON, s23 (transparency only, in French) from a `.txt`, and s27 (minimal risk) from a `.docx`.
- **Chosen:**
  - **One deadline per request:** 50 s from the start of the request, passed to every `chat()` of `/ask` and `/classify`. After it, no provider is started and the API answers 503.
  - **The cap stays in memory, documented here:**
    - `DailyCap` counts only the requests that reach a model, so a 401, 413, 415 or 422 costs nothing.
    - Each instance counts on its own, and a restart resets the count.
    - Step 13 deploys with `--max-instances 1`.
  - **A spent quota is skipped:** a Retry-After over 60 s blocks that provider until it has passed, so the fallback answers at once.
  - **Errors:**
    - 401 for a bad key;
    - 422 for bad input, or a file with no readable text;
    - 413 for a file over 2 MB;
    - 415 for another file type;
    - 429 past the cap;
    - 503 when no model answers in time, or when the agent returns no valid classification.
- **Why:**
  - **The deadline:** Cloud Run stops a request after 60 s. `/classify` can make up to 8 model calls, and a 25 s budget per call would let one request run for minutes.
  - **The cap protects the free quotas, not money.** The Gemini key's project has no billing account, so the cost stays at EUR 0 even after a reset. On a single instance, a shared counter would add a dependency and credentials for little gain.
- **Revisit if:**
  - **More instances, or resets used to get around the cap:** the demo runs on more than one instance, or someone uses cold starts to reset the count. Then move the count to Firestore.
  - **Latency:** the p95 approaches the 50 s budget in step 14's load test.
